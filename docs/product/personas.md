# 角色

四套產品各有使用者，不是「成交前／成交後」兩種人。進場畫面見 [UI／UX](ux.md)。工作區權限見 [總規格](spec.md#角色與權限)。系統分析見 [analysis.md](analysis.md)。仲介見 [marketplace.md](marketplace.md)（門檻後）。

## 軟體工程師（控制台；現況）

**要：** 跨公司、跨專案開工；與本機 AI 編碼工具合作；堆疊真話；把工時與解決的 Issue 回報所屬公司。  
**不要：** 被逼改用某家公司的前後台當唯一工具。  
**進場：** **現況**桌面控制台。申報目的地可多家（規劃上傳閉環）。

## 經營層（總經理／技術長）

**要：** 一屏看到延期、無人接的派工、毛利低於門檻。  
**不要：** 甘特圖細節、幫工程師排今天的 Issue。  
**進場：** **規劃**工作區戰情室（下一實作）。現況可看工時匯出與進件軌跡，但沒有公司級一屏。

## 交付主管

**要：** 跨專案人力衝突、外包是否超約、本週要驗收的里程碑。  
**不要：** 編譯 Log。  
**進場：** 戰情室 → 派工全貌 → 單一專案。

## 專案經理（PM）／分析師

**要：** 客戶與合約、階段、甘特、誰被派到這單、進件到驗收、專案貢獻彙總。  
**現況已有：** 控制台需求工作台（進件、Issue、驗收關卡）。  
**規劃補上：** 工作區客戶主檔、甘特、貢獻檢視；上游「概念變 Issue」走系統分析輔助（P3）。

## Tech Lead

**要：** 堆疊真話、MCP 政策、誰在改哪條服務。  
**進場：** **現況**桌面控制台為主；工作區只看派工與負載，不取代本機指揮台。

## 工程師（正職／工作區角色）

**要：** 啟動堆疊、編譯、接任務、工時自動切、卡住求救。  
**幾乎不到瀏覽器。** 工作區只做：確認本週工時、看自己的薪資條／專案分攤。  
執行狀態圖在**桌面控制台**畫；對自己設定的公司公開回報端申報。控制台不必先屬於這家公司。

## 外包窗口與外包工程師

**要：** 只看己方人員、己方合約專案、可報的工時。  
**不能：** 看別家費率、全公司毛利、其他客戶合約額。  
外包工程師同樣用桌面控制台（GitHub 帳號），可同時對其他公司申報；送到本公司後由窗口或我方 PM 核准。亦可經 API 金鑰由第三方工具代送（符合公開契約）。

## 人資／財務

**要：** 人員主檔、計薪規則、月結核准、專案人事成本匯出。  
**不要：** 當專案管理工具用。  
**進場：** 人員 → 薪資週期 → 預算報表。第一版匯出 CSV／明細，不內建報稅。

## 需求窗口／PO（系統分析輔助；規劃 P3）

**要：** 用口語與素材把概念變成需求文件、規格、可指派 Issue。  
**不要：** 先學 Git、先裝控制台、被推進仲介當唯一入口。  
**進場：** **規劃**系統分析輔助站。產出後工程師在控制台收得到指派。

## 需求組織窗口（仲介；規劃 P4，門檻後）

**要：** 發案（可附 P3 產物）、找到通過認證的工程師、成交拿到合同、拆帳。  
**不要：** 在仲介裡重做完整系統分析。  
**進場：** **規劃**仲介網站（僅開門條件通過後）。工作區可另開、不經仲介。

## 工程師會員（仲介；門檻後）

**要：** 找到適合的專案與公司；認證過就能應徵；成交後用自己的控制台做工與申報。  
**不要：** 把履歷社群當主場、被當成派遣員工。  
**進場：** **規劃**仲介找專案；**現況**做工仍在桌面控制台。
