# 角色

三套機制各有使用者，不是「成交前／成交後」兩種人。進場畫面見 [UI／UX](ux.md)。工作區權限見 [總規格](spec.md#角色與權限)。仲介見 [仲介平台](marketplace.md)。

## 需求組織窗口（仲介）

**要：** 用精靈把專案與人力資格寫清楚；找到通過認證的分析／設計／開發／測試；成交拿到合同；之後有管理面。  
**不要：** 先安裝控制台、先學會 Git。  
**進場：** **規劃**仲介網站。若該組織使用工作區，成交後可從仲介進入該租戶；工作區也可不經仲介直接開。

## 工程師會員（仲介；分析／設計／開發／測試）

**要：** 找到適合的專案與公司；認證過就能應徵；成交後用自己的控制台做工與申報。  
**不要：** 把履歷社群當主場、被當成派遣員工。  
**進場：** **規劃**仲介找專案；**現況**做工仍在桌面控制台。

## 經營層（總經理／技術長）

**要：** 一屏看到延期、無人接的派工、毛利低於門檻、AI 授權有沒有換成可驗收交付。  
**不要：** 甘特圖細節、幫工程師排今天的 Issue。  
**進場：** **規劃**戰情室。現況可看工時匯出與進件軌跡，但沒有公司級一屏。

## 交付主管

**要：** 跨專案人力衝突、外包是否超約、本週要驗收的里程碑。  
**不要：** 編譯 Log。  
**進場：** 戰情室 → 派工全貌 → 單一專案。

## 專案經理（PM）／分析師

**要：** 客戶與合約、階段、甘特、誰被派到這單、進件到驗收。  
**現況已有：** 需求工作台（開 GitHub Issue、指派、驗收）。  
**規劃補上：** 客戶主檔、甘特、跨倉專案時程、分析師與工程師投入。

## Tech Lead

**要：** 堆疊真話、MCP 政策、誰在改哪條服務。  
**進場：** **現況**桌面控制台為主；公司平台只看派工與負載，不取代本機指揮台。

## 工程師（正職）

**要：** 啟動堆疊、編譯、接任務、工時自動切、卡住求救。  
**幾乎不到瀏覽器。** 公司平台只做：確認本週工時、看自己的薪資條／專案分攤。  
執行狀態圖在**桌面控制台**畫；對自己設定的公司接收 API 申報。控制台不必先屬於這家公司。

## 外包窗口與外包工程師

**要：** 只看己方人員、己方合約專案、可報的工時。  
**不能：** 看別家費率、全公司毛利、其他客戶合約額。  
外包工程師同樣用桌面控制台（GitHub 帳號），可同時對其他公司的接收端申報；送到本公司後由窗口或我方 PM 核准。

## 人資／財務

**要：** 人員主檔、計薪規則、月結核准、專案人事成本匯出。  
**不要：** 當專案管理工具用。  
**進場：** 人員 → 薪資週期 → 預算報表。第一版匯出 CSV／明細，不內建報稅。
