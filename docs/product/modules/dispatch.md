# 派工

**規劃**（公司工作區 P2 寫全貌；GitHub 與控制台任務列為 **現況** 已接上的任務面）。貢獻入帳見 [公開回報契約](../reporting.md)。

## 要解決的問題

派工今天裂成三處：GitHub assignee、聊天室「你去支援一下」、Excel 的人力表。主管看不見誰超載；工程師在控制台只看到「我的＋未指派」，這是對的，但公司還需要一張**全貌**。

## 原則

- **GitHub 是任務面。** Issue／PR 的 assignee 與 Project 成員仍是執行來源。
- **公司平台是人力面。** 誰在哪段時間屬於哪個專案、佔用多少小時、有沒有合約授權。
- 派工寫回 GitHub（加 assignee 或 Project collaborator）應可開關。預設：對已綁定的 repo **寫回 Issue assignee**；失敗則標「待同步」，不假裝已派到 GitHub。

## 派工單

一筆派工包含：人員、專案、期間、規劃小時／週、角色（分析師、工程師、Lead、PM）、來源（手動／由 Issue 轉入）、狀態（規劃／進行／完成／取消）。

可選關聯：一個或多個 Issue 編號、里程碑。

衝突偵測（寫入時擋或警告）：

- 時段與另一筆派工重疊且合計超過每週上限
- 外包人員不在該專案的合約授權名單
- 人員狀態不是在職

## 與控制台的整合

| 面 | 誰看 | 規則 |
|----|------|------|
| 開發工作台任務列 | 工程師（現況） | 預設「我的＋未指派」 |
| 需求看板 | PM（現況） | 全部未關閉與指派 |
| 派工全貌 | 交付主管／PM（規劃） | 按週的人 × 專案矩陣 |
| 我的派工 | 工程師 Web（規劃） | 只讀期間與專案；改碼仍在控制台 |

控制台不顯示全公司矩陣。公司平台不顯示編譯與 Log。

## 建議派工（MVP 可弱）

依技能標籤、剩餘可派小時、專案技術棧（來自服務掃描的粗標，可人工改）排序前幾名。**建議不是自動指派。** 自動指派不進 MVP。

## 關鍵畫面

- **週矩陣：** 列是人（可按外包商分組），欄是工作日（週一到五含日期）加本週已派／上限。格子是專案色塊與小時。超載變紅。小時欄固定寬，不被側欄裁切。
- **專案投入：** 此專案目前有誰、角色、期間、關聯 Issue。
- **未派任務：** 已發出、無 assignee 或無派工單的 Issue，從 GitHub 拉。

## 驗收條件（MVP）

- 從全貌把一位工程師派到專案一週，控制台該使用者能在任務面看到對應 Issue（若已寫回）。
- 外包人員派到未授權專案被拒絕並說明原因。
- 超載有視覺與寫入警告；`delivery` 可強制寫入並留審計。
- 取消派工不會刪已上傳工時。
