# 戰情室

**規劃。** 給經營層與交付主管的一屏，不是工程師的第二個看板。

## 要解決的問題

總經理不該進 Jira 或問五個 PM 才能知道：哪個專案要爆、誰沒人接、哪單毛利已經紅了。戰情室只呈現**例外與健康**，細節鑽進專案、派工、預算。

## 一屏內容

| 區塊 | 資料來源 | 預設規則 |
|------|----------|----------|
| 專案健康 | 專案時程、階段、進件逾期 | 綠：目標日內且階段正常；黃：14 日內到期或階段滯留；紅：已逾期或驗收卡住 |
| 人力 | 派工 | 紅：超載或關鍵角色空缺；黃：本週利用率低於公司門檻（待案） |
| 派工缺口 | GitHub 未指派＋已發出進件 | 紅：超過 N 天無人接（公司可設，預設 3 個工作日） |
| 工時異常 | 上傳時段 | 黃：連續 3 日無上傳（已派工的人）；紅：單日超上限未核准 |
| 毛利 | 預算 | 用公司毛利率門檻；無收入的內部專案可排除或另列 |

數字圖都要標期間（本週／本月）。規則可調，出廠值必須能直接用。

## 不是什麼

- 不是即時監控編譯與連接埠（那是控制台摘要列）。
- 不是 BI 任意拖曳報表。MVP 固定區塊，避免做成第二個 Power BI。
- 不是客戶可登入的入口。

## 鑽取

點專案健康 → 專案首頁（甘特＋派工＋損益卡）。  
點人力紅燈 → 週矩陣，過濾超載。  
點毛利 → 該專案損益卡。

`exec` 預設只讀。`delivery` 可從戰情室跳去改派工。`engineer` 不進戰情室（選單不出現）。

## 關鍵畫面

- **戰情室首頁：** 上列 KPI（進行中專案數、紅燈數、本月預估毛利），下列專案卡與例外清單。
- **專案卡：** 名稱、客戶、階段、目標日、人數、健康色、毛利色。十張以內一屏能掃完；更多用篩選「只看紅黃」。

行動裝置：保證首頁 KPI 與例外清單可讀、可點進專案只讀頁。不保證改甘特。

## 驗收條件（MVP）

- `exec` 登入落地就是戰情室，不必找選單。
- 人為把專案目標日設到昨天，卡片變紅，無須重算批次超過五分鐘（準即時即可）。
- 外包窗口與工程師看不到戰情室。
- 內部無收入專案可標記「不列入毛利 KPI」，避免把戰情室變成全紅。
