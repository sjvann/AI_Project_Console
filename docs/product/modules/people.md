# 人員與外包

**規劃**（公司工作區 P2；**下一實作**）。控制台只用 GitHub 帳號當人的主鍵，沒有員工檔與外包商——那是**現況**的上限。仲介會員檔在 [仲介平台](../marketplace.md)（門檻後），不是本模組。本模組可獨立使用；公開回報契約依名冊握手；仲介成交時亦可交換資料寫入名冊，**不必先走仲介**。

## 要解決的問題

軟體公司的「人」不是一張員工卡。現場同時有正職、個人工作室、承攬公司派駐。主管問「下週誰能進這個客戶」時，試算表與 GitHub org 對不上；外包窗口不該看到別家的人與費率。

## 人員主檔

每位人員必填：顯示名、雇用類型、狀態（在職／停用／黑名單）。選填：GitHub 帳號、電子郵件、技能標籤、預設工時上限（例如每週 40）、所屬部門、直屬主管、所屬外包商。

| 雇用類型 | 計薪預設 | 派工 |
|----------|----------|------|
| 正職 | 月薪＋可選專案獎金 | 可派任何已授權專案 |
| 專案外包（個人） | 時計或專案包 | 僅合約載明的專案 |
| 承攬派駐 | 時計（對外包商）或月結對帳 | 僅該外包商被授權的專案 |

技能標籤用於派工建議（例如 `blazor`、`dba`、`analyst`），**不是**強制職等系統。MVP 不做人資績效考核。

## 外包商

外包商主檔：公司名、統編（選填）、窗口人員、有效期間、預設費率表。費率可依職級或技能覆寫到單一派駐人員。

外包窗口（`vendor_admin`）只能：

- 看己方人員名單與己方專案的工時
- 停用己方已離場人員（需我方 `hr` 或 `pm` 確認才從專案撤派）
- 不能看毛利、他司人員、客戶合約總額

## 可用度

每人每天／每週的「可派工時段」來自：

1. 雇用類型的標準工時
2. 已核准派工佔用
3. 人工標記的不可派（請假、客戶現場、教育訓練）——MVP 只做日期區間標記，**不**做法規特休引擎

戰情室與派工用「剩餘可派小時」與「超載」兩個數，不要第三種口徑。

## 與控制台的關係

控制台是工程師自己的工具，不隸屬本公司名冊。本公司只公布接收 API；參與專案的工程師在控制台把該 URL 加成申報目的地。

握手（`GET /api/v1/me`）用控制台 GitHub 登入對到 `github:{login}` → `personId`。通過才接受上傳。從**線上招募**進來的外部工程師，由人資／管理員發 GitHub 邀請後建檔並綁定；他們用桌面控制台申報，不登公司後台。對不上的上傳進「待歸戶」佇列，由人資在人員卡片綁定。尚未綁定的人可以出現在人員表，但不能自動對 PR。同一 GitHub 帳號可以對**另一家**公司的接收端申報，那是別家名冊的事。

## 關鍵畫面

- **人員名冊：** 篩選雇用類型、外包商、技能、狀態。列上顯示本週已派／上限。
- **人員卡片：** 分頁「主檔｜派工與工時」。主檔含合約／費率（權限內）。派工與工時左欄目前派工、右欄近期工時表（狀態中文；滿 8h 黃、10h 紅）。
- **外包商：** 卡片網格看摘要（對帳小時、授權專案、派駐）。編輯費率與有效期進對話框，改費率必填原因。

## 驗收條件（MVP）

- 能建立正職與兩種外包，且外包窗口登入後看不到他司。
- 同一 GitHub 帳號不能綁兩個在職人員。
- 停用人員後不能新派工；已發生工時仍可查。
- 技能與可用度能被派工模組讀到。
