# 願景與買家

**規劃**為主。控制台能力標 **現況**。仲介平台與公司工作區皆為規劃，不能講成已出貨。

## 一句話

同一品牌下三套獨立機制：仲介讓有軟體需求的公司與工程師成交並抽成；需求公司用工作區管人與專案；工程師承接後用本機控制台做工與申報。三者交換資料，不互相內嵌。加入免費，認證要強。

## 三套獨立機制

| 機制 | 狀態 | 給誰 | 誰營運 |
|------|------|------|--------|
| **仲介平台** | 規劃；**下一實作** | 需求公司、獨立工程師 | 我們營運的公開 SaaS |
| **公司工作區** | 規劃；可獨立開帳。現有 Company.* 沿用，改租戶 | 需求公司管理工程師（經營／交付／人資／財務） | 預設我們主機上的租戶；自架改後期 |
| **控制台** | 現況 | 任何工程師（承接專案後） | 工程師本機安裝包 |

切割以 [總規格・三層產品](spec.md#三層產品) 與 [仲介平台](marketplace.md) 為準。工作區**不是**仲介的成交後模組。

## 買家

三邊都可以是買家。加入仲介會員不收費；仲介營收來自**成交後的仲介費**。工作區與控制台各有自己的使用情境，不必先走仲介。

| 邊 | 誰 | 為什麼來 |
|----|-----|----------|
| 需求方（仲介） | 任何有軟體專案的組織：傳統企業、新創、機關、內部 IT、SI | 發布專案與人力資格，找到通過認證的分析／設計／開發／測試 |
| 需求公司（工作區） | 同上，以及已有工程團隊、要管人／工時／毛利的公司 | 管名冊、派工、工時確認、薪資匯出、戰情；工程師可來自仲介成交，也可本來就在名冊 |
| 供給方 | 系統分析、系統設計、程式開發、系統測試（個人或工作室） | 找到適合的專案與公司；用自己的控制台做工與申報，不必改用對方的桌面套件 |

**不是首輪：** 要買汎用 ERP／HRIS 的集團人資、要勞務派遣牌照的人力銀行、要把原始碼託管給我們的客戶。

舊文件把「10–200 人軟體公司自架營運」改列為仲介需求方的一種，並把工作區改成「成交後才開」——那是把兩個問題疊在一起。工作區仍是獨立機制；自架改後期是部署選擇，不是產品身分。

## 要完成的工作（Jobs to be done）

1. 需求公司用**網頁精靈**寫出專案範圍、人力需求與資格，不必先會 Git。（仲介）
2. 通過認證的工程師能找到適合自己角色與技能的專案；公司能邀請或接受應徵。（仲介）
3. 雙方達成協議後拿到合同套件（含保密），平台記下仲介費。（仲介）
4. 需求公司能管人、專案、工時確認與毛利；溝通走 GitHub Issue。（工作區；可獨立，也可接收仲介成交事件）
5. 工程師承接專案後，用本機控制台展開作業（進件、堆疊、編譯）並對選定工作區申報時數。同一人可對多家工作區申報。（控制台）

## 市場判斷（為什麼現在）

雲端 PM 強在工作單，弱在本機編譯。AI IDE 會改碼，弱在治理。工時工具會計時，弱在合約與外包。人力平台強在履歷，弱在把需求寫清楚、弱在成交後怎麼真的開工。

這是**三個問題**，不要合成一個產品：

- 找不到通過認證的對方、沒有合同與抽成 → 仲介
- 需求公司找不到地方管人、派工、工時與毛利 → 工作區
- 工程師承接後沒有本機堆疊與工時真相 → 控制台（現況已補）

下一實作仍是仲介第一刀。工作區與控制台用契約接上，不當成仲介畫面的下一頁。

## 刻意不做

| 不做 | 原因 |
|------|------|
| 取代 Jira／Azure Boards | 任務面以 GitHub Issue 為準 |
| 取代 Cursor／Copilot | Agent 是操作者；控制台是本機真相 |
| 汎用 ERP、總帳、報稅、勞健保申報 | 工作區匯出給既有財務；仲介第一刀只記應收仲介費，不做金流託管 |
| 把客戶原始碼收到我們的雲 | 控制台本機；上傳僅時段與狀態圖 |
| 把控制台做成某家公司的前後台 | 控制台給所有工程師。見 [三層產品](spec.md#三層產品) |
| 勞務派遣、自動媒合、履歷社群 | 仲介是專案承攬，不是 104／派遣公司 |
| 在仲介層重做薪資／毛利／戰情室 | 那是工作區，沿用現有公司平台碼 |
| 把工作區做成仲介的成交後模組 | 工作區可獨立開帳；成交只觸發資料交換 |

**已翻轉的舊非目標：** 公開 SaaS 多租戶與需求公司自助發布，改為**仲介預設**。客戶自架工作區改列後期。

## 成功長什麼樣

- Tech Lead 用自己的倉 **90 分鐘**走完控制台（現況）。不必先有仲介或工作區。
- 一組通過認證的需求公司與工程師，走完發布 → 應徵／邀請 → 雙方同意 → 合同產生；成交事件寫入該組織工作區；控制台申報第一筆工時（規劃，仲介第一刀驗收的**交換閉環**）。
- 需求公司打開工作區，看得到專案、人、待確認工時，不必問「那個專案怎樣」（規劃，工作區；來源可以是仲介，也可以是公司自己建的專案）。
