# 願景與買家

**規劃**為主。控制台能力標 **現況**。公司工作區、系統分析輔助、仲介皆為規劃，不能講成已出貨。

## 一句話

同一品牌下四套獨立產品：工程師用本機控制台做工與申報；公司用工作區收公開契約回報並管人與專案；系統分析輔助把概念變成可追蹤 Issue；門檻通過後，仲介才讓非軟體業廠商發案、找工程師並拆帳。四套交換資料，不互相內嵌。

## 四套獨立產品

| 代號 | 產品 | 狀態 | 給誰 | 誰營運 |
|------|------|------|------|--------|
| **P1** | **控制台** | 現況 | 任何軟體工程師（跨公司、跨專案） | 工程師本機安裝包 |
| **P2** | **公司工作區** | 規劃；**下一實作** | 要管人／專案／工時確認／毛利的公司 | 預設我們主機租戶；自架後期 |
| **P3** | **系統分析輔助** | 規劃；P2 之後 | PM／分析師／有需求概念但不會寫規格的窗口 | 我們營運的 Web（工作名稱；品牌待定） |
| **P4** | **仲介平台** | 規劃；**門檻產品** | 有資訊需求、但不是軟體公司的廠商；獨立工程師 | 我們營運的公開 SaaS |

切割以 [總規格・四套產品](spec.md#四套產品) 為準。工作區**不是**仲介的成交後模組。系統分析輔助**不是**仲介精靈的升級。

## 買家

四邊都可以是買家。控制台與工作區不必先走仲介。仲介加入免費（規劃）；營收來自成交後的仲介費。工作區與控制台各有自己的使用情境。

| 邊 | 誰 | 為什麼來 |
|----|-----|----------|
| 工程師（控制台） | 分析、設計、開發、測試（個人或工作室） | 跨公司專案開工；與本機 AI 編碼工具合作；把工時與解決的 Issue 回報所屬公司 |
| 需求公司（工作區） | 已有或要管工程團隊的公司（含 SI） | 收符合契約的回報、按專案看貢獻、管名冊／派工／毛利／發薪匯出 |
| 分析／PM（系統分析輔助） | 要把口語需求變成可追蹤工作項的人 | 概念 → 需求文件 → 規格 → Issue，並指派給控制台工程師 |
| 非軟體業廠商（仲介） | 有資訊需求、不會自己寫 PRD 的組織 | 發案、找通過認證的工程師、管專案、拆帳（**門檻後**） |

**不是首輪：** 要買汎用 ERP／HRIS 的集團人資、要勞務派遣牌照的人力銀行、要把原始碼託管給我們的客戶。

## 要完成的工作（Jobs to be done）

1. 工程師用本機控制台展開作業（堆疊、編譯、GitHub、進件）並對選定公司申報時數與 Issue。同一人可對多家公司申報。（控制台；現況＋規劃上傳閉環）
2. 公司用工作區收**任何符合公開回報契約**的貢獻，按專案合併看工程師貢獻；並管人、派工、工時確認與毛利。（工作區；下一實作）
3. 窗口用系統分析輔助把需求概念轉成需求文件、規格、可追蹤 Issue（含測試／debug 工作項），工程師在控制台收得到指派。（系統分析輔助）
4. 門檻通過後：非軟體業廠商經仲介發案、媒合、合同與拆帳；成交事件可寫入工作區。（仲介）

## 市場判斷（為什麼現在）

雲端 PM 強在工作單，弱在本機編譯。AI IDE 會改碼，弱在治理。工時工具會計時，弱在合約與外包。人力平台強在履歷，弱在把需求寫清楚、弱在成交後怎麼真的開工。

這是**四個問題**，不要合成一個產品：

- 工程師承接後沒有本機堆疊與工時真相 → 控制台（現況已補）
- 公司收不到標準化的工時／Issue 回報、管不了人與毛利 → 工作區（下一實作）
- 不會把概念變成可追蹤 Issue → 系統分析輔助
- 非軟體業找不到人、沒有合同與拆帳 → 仲介（門檻後）

下一實作是公司工作區與公開回報契約。仲介不當成「下一頁必做」。

## 刻意不做

| 不做 | 原因 |
|------|------|
| 取代 Jira／Azure Boards | 任務面以 GitHub Issue 為準 |
| 取代 Cursor／Copilot | Agent 是操作者；控制台是本機真相 |
| 汎用 ERP、總帳、報稅、勞健保申報 | 工作區匯出給既有財務；仲介第一刀只記應收仲介費，不做金流託管 |
| 把客戶原始碼收到我們的雲 | 控制台本機；上傳僅時段、狀態圖、Issue 參照 |
| 把控制台做成某家公司的前後台 | 控制台給所有工程師。見 [四套產品](spec.md#四套產品) |
| 勞務派遣、自動媒合、履歷社群 | 仲介是專案承攬，不是 104／派遣公司 |
| 在仲介層重做薪資／毛利／戰情室 | 那是工作區 |
| 把工作區做成仲介的成交後模組 | 工作區可獨立開帳；成交只觸發資料交換 |
| 把系統分析輔助塞進仲介當發案精靈 | 那是獨立產品 P3 |
| 把模啟寫進本線產品層 | 模啟是另一條產品；控制台只當專案目錄 |

## 成功長什麼樣

- Tech Lead 用自己的倉 **90 分鐘**走完控制台（現況）。不必先有工作區或仲介。
- 公司打開工作區，收得到符合契約的第一筆回報（控制台或其他用戶端），按專案看得到貢獻；人員／派工／工時確認可跑完一個薪資週期（規劃，P2）。
- 非工程師窗口在系統分析輔助走完「概念 → Issue」，工程師在控制台收得到指派並開工（規劃，P3）。
- 上述 P3 閉環重複驗證通過後，非軟體業廠商才經仲介走完發案 → 成交 → 拆帳（規劃，P4）。
