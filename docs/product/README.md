# 產品規格

這份規格給**產品與下一階段實作**對齊用。一般使用者請走 [使用文件](../README.md)，不必從這裡開始。

## 現況與規劃

| 標籤 | 意思 | 現在能不能演示 |
|------|------|----------------|
| **現況** | 已在 Windows／macOS／Linux 桌面控制台出貨（**0.6.19**） | 能。見 [90 分鐘導入](../team/trial-90min.md) · [現行版本](../user/whats-new.md) |
| **規劃** | 公司工作區（下一實作）、系統分析輔助、仲介（門檻後） | 不能當成已出貨。見 [路線圖](roadmap.md) |

銷售與簡報必須沿用這兩個標籤。把規劃講成現況，等於對買家說謊。

本目錄的 `intake.json`、`design/`、`intake-assets/` 是**控制台需求進件**寫入的資料，不是這份規格書。規格書是下面這些 Markdown。

## 四套獨立產品、同一品牌

因果是**建構順序**，不是「成交後才解鎖下一頁」。四套不共用資料庫，只靠契約交換。

| 代號 | 產品 | 狀態 | 機制 | 技術 |
|------|------|------|------|------|
| **P1** | **AI_Project 控制台** | 現況 | 工程師跨公司／跨專案做工，與本機 AI 編碼工具合作；申報工時與 Issue | .NET 10、Blazor UI；現況 Photino 宿主，目標 Avalonia 承載同一套 UI |
| **P2** | **AI_Project 公司工作區** | 規劃；**下一實作** | 公司端管人／專案／毛利；**公開回報契約**收任何符合格式的用戶端 | .NET 10 Blazor Web App；獨立安裝產物；我們主機與自架同一通道 |
| **P3** | **系統分析輔助**（工作名稱；品牌待定） | 規劃；P2 之後 | 概念 → 需求文件 → 規格 → 可追蹤 Issue；指派給控制台工程師 | 新建 Blazor Web App；獨立安裝；見 [系統分析輔助](analysis.md) |
| **P4** | **AI_Project 仲介平台** | 規劃；**門檻產品** | 非軟體業發案、媒合、專案管理、拆帳 | .NET 10 Blazor Web App、我們營運的 SaaS；見 [仲介平台](marketplace.md) |

**下一實作是 P2（公司工作區＋公開回報契約）**，不是仲介。仲介僅當 P3 證明「能把非工程師需求變成可指派 Issue」之後才開。切割以 [總規格・四套產品](spec.md#四套產品) 為準；回報契約見 [公開回報契約](reporting.md)。

模啟／ModuLaunch 是另一條產品，**不寫進本線產品層**。控制台對它與對任何 repo 一樣：選專案目錄即可。
