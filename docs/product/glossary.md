# 詞彙

先會這份就夠跟文件對得上。標 **規劃** 的詞不要講成安裝包已有。更完整的產品詞見 [總規格・詞彙](spec.md#詞彙)。

## 控制台（現況）

| 詞 | 意思 |
|----|------|
| **專案目錄** | 你要管的那份本機資料夾（通常是 git 倉根，或薄工作區） |
| **服務** | 可啟動的程式（API、網站）。「服務」頁籤 |
| **專案（編譯）** | 倉裡偵測到的專案（`.csproj`、`package.json`、`pyproject.toml` 等） |
| **用途** | 專案或服務名稱旁的一句產品功能描述。每個掃描到的專案都要有 |
| **就緒** | 服務已啟動且健康檢查通過（顯示「線上」） |
| **需重編** | 原始碼比上次編譯結果新，建議先編譯再啟動 |
| **求救** | 把錯誤說明交給你選的 Agent（Cursor 等），不是把程式送到雲端代管 |
| **MCP** | Agent 呼叫控制台的通道（查狀態、編譯、啟停） |
| **佔用** | 規劃（軌道 O）。目前這一筆長工作（建置／測試／掃描／Git／啟停／Agent 編譯）；頂欄條顯示，被擋按鈕事先停用。見 [架構 AD-32](architecture.md) |
| **專案問答** | 控制台內對談，用你設定的 OpenAI 相容端點＋本機唯讀工具，不外開 IDE |
| **ai-project.json** | 可選的工作區清單。沒有也能掃描；多倉或服務對不上時再補 |
| **進件** | 需求工作台裡的需求（REQ）或設計變更（ECR），發出後變 GitHub Issue |

## 四套產品（規劃為主）

| 詞 | 狀態 | 意思 |
|----|------|------|
| **控制台（P1）** | 現況 | 工程師本機做工、堆疊、申報 |
| **公司工作區（P2）** | 規劃；下一實作 | 公司管人、專案、工時確認、毛利；收公開回報契約 |
| **公開回報契約** | 規劃 | 工時／Issue／貢獻的 HTTPS 契約；任何符合格式的用戶端都可送。見 [reporting.md](reporting.md) |
| **系統分析輔助（P3）** | 規劃 | 概念 → 需求文件 → 規格 → 可追蹤 Issue。工作名稱；品牌待定。≠ 模啟系統分析者台；≠ 模啟「P3」產業包 |
| **仲介平台（P4）** | 規劃；門檻產品 | 媒合成交、合同、拆帳。本線 P3 門檻通過後才開 |
| **成交** | 規劃 | 雙方接受協議；可另發事件寫入工作區 |
| **申報目的地** | 規劃可多筆；現況可先填一組接收 URL | 控制台上一家工作區的 HTTPS 接收端；連線登錄的一種角色，測試通過才啟用 |
| **連線登錄** | 規劃 | 跨產品端點清單（URL、契約版本、測試結果、啟用）。預設關閉。見 [架構 AD-16](architecture.md) |
| **主題包** | 規劃 | 企業色盤 JSON＋CSS 變數；語意紅黃綠不可當品牌主色。見 [UI／UX](ux.md) |
| **GitHub 主鍵** | 現況＋規劃 | `github:{login}`，工時與名冊對人 |
| **專案貢獻** | 規劃 | 工作區依專案彙整各工程師回報的工時、Issue、貢獻類型 |

## 模啟關係（姊妹產品，不進四套）

| 詞 | 意思 |
|----|------|
| **模啟（ModuLaunch）** | 產業應用 OS（runtime、熱加入、授權、四套角色台）。對外主品牌；本線控制台是可選本機加速器 |
| **L0 敘事** | 模啟＝核心；控制台＝可選加速。不對等並列、不把模啟塞進四套產品層 |
| **L1 薄契約** | 選模啟目錄掃描（已可）；詞彙對齊；可選 SA Issue ↔ 進件對照（文件 only）。不寫深整合程式 |
| **模啟・系統分析者台** | 已出貨；定稿 module-definition／變體。≠ 本線系統分析輔助。見 [analysis.md](analysis.md#與模啟系統分析者控制台) |
| **模啟 P3** | 模啟路線圖的第二產業超薄包。與本線「P3 系統分析輔助」代號撞車；對外寫全名 |

角色與權限表見 [總規格](spec.md#角色與權限)。
