# 進件（產品）

**現況：** 控制台需求工作台已出貨。畫面與關卡見 [需求工作台](../user/intake.md)。資料寫在目前工作區 `docs/product/intake.json`（以及 `design/`、`intake-assets/`），那是**被管專案**的進件，不是本規格書。

**規劃：**

| 產品 | 角色 |
|------|------|
| [系統分析輔助](analysis.md)（P3） | 把概念變成需求文件、規格、可追蹤 Issue（含測試／debug）；工程師在控制台收得到指派 |
| [公司工作區](modules/projects-clients.md)（P2） | 只讀進件／貢獻彙總；不另做進件 UI |
| [仲介平台](marketplace.md)（P4，門檻後） | 發案可引用 P3 產物；不取代控制台進件，也不重做完整系統分析 |

## 現況關卡（控制台）

草稿 → 設計就緒 → 已拆解 → 已發出 → 實作中 → 驗證中 → 可審查 → 已入主線 → 已發行 → 已部署 → 已驗收 → 已報帳

沒有驗收條件不能發出 Issue。介面新需求要草圖；介面設計變更要現況剪圖。CI 未綠不能合併。驗收要勾完條件。

## 規劃裡不要重複做的

控制台已經管本機進件與 GitHub Issue。公司工作區讀這些真相，不另做一套進件 UI。系統分析輔助負責倉外／上游的「概念 → Issue」。仲介只負責媒合與成交，不把發案精靈當成系統分析產品。
