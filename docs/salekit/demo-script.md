# 演示腳本

現場只演示 **現況**。仲介與工作區用一句話指向 [產品規格](../product/README.md)，不要假裝有媒合或戰情室畫面。

對齊 [90 分鐘導入](../team/trial-90min.md)。聽眾以 Tech Lead + PM 為主；經營層在旁邊聽「關卡與工時」即可。

## 會前

- 對方同意用**他們自己的倉**（多服務最好）。沒有就準備一份可公開的示範倉，並說清楚不是他們的生產數字。
- Windows 安裝包已下載；WebView2、Git、gh、.NET SDK（若要編譯被管專案）已就緒。
- 關閉會把機密 Log 投到大螢幕的服務。

## 建議 90 分鐘

| 分鐘 | 做什麼 | 要讓他們看見 |
|------|--------|----------------|
| 0–10 | 安裝、選專案或從 GitHub 開啟、環境體檢 | 不是顧問案；十分鐘進得去 |
| 10–25 | 需重編、編譯過期、啟動、開前端、看 Log | 堆疊真話，不是看板 |
| 25–40 | 登入 GitHub、Pulse、任務列「我的＋未指派」 | 人的主鍵是 GitHub |
| 40–55 | 需求台開一張 Issue：標題、說明、可選指派 | 對齊 GitHub，不塞關卡 |
| 55–70 | 工時徽章、儀表板、匯出說明 | 對帳不是回憶 |
| 70–85 | 求救一次；若有 MCP，請 Agent 用值班摘要，不要猜連接埠 | Agentic 閉環＋審計 |
| 85–90 | 收尾：現況能買什麼；規劃的仲介與工作區是規格書不是安裝包 | 誠實 |

## 不要做

- 不要現場改對方生產主線。
- 不要保證 Agent 一次改對。
- 不要打開尚未實作的戰情室或薪資畫面。
- 不要用示意圖表冒充對方數據。

## 演示後作業

寄 [一頁紙](one-pager.md) 與文件站連結。若對方要外包／毛利／發薪，另約規格書走讀，不要塞進這 90 分鐘。
