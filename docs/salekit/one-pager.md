# AI_Project · 給軟體工程師與軟體公司的一頁紙

**本機交付指揮台**（掃描、編譯真相、啟動、GitHub、工時、Agent）。給軟體工程師面對不同公司、不同專案，並與本機 AI 編碼工具一起完成任務。**程式碼不上我們的雲。**

模啟／ModuLaunch 是另一條產品（產業應用 OS），**不是**本線的下一層。控制台對模啟與對任何 repo 一樣：選專案目錄即可；分開安裝，不取代模啟。

**規劃（尚未出貨）：** 同一品牌另有公司工作區（下一實作）、系統分析輔助、仲介（門檻後）。簡報勿把規劃講成安裝包已有。

## 痛點（你們多半已經有工具）

工作單在系統裡，程式在工程師電腦，工時在試算表，外包在另一份合約。AI 會改碼，卻看不到需重編與就緒。公司端收不到標準化的工時／Issue 回報，專案毛利結案才知道。

## 現況可買（Windows 桌面控制台 · P1）

選專案 → 掃描服務與需重編 → 一鍵啟動 → GitHub 提交與 PR → 開 Issue 到驗收 → 工時從開啟專案起算並匯出對帳單。卡住把上下文交給本機 Cursor 等 Agent；MCP 讓 Agent 回查堆疊，動作可審計。

90 分鐘用**你們自己的倉**試完，見 [導入](../team/trial-90min.md)。

## 規劃中（尚未出貨，見產品規格）

建構順序（不是「成交後才解鎖」）：

| 代號 | 產品 | 狀態 | 一句話 |
|------|------|------|--------|
| **P2** | **公司工作區** | **下一實作** | 收公開回報契約（不限控制台）、按專案看貢獻；人員／派工／工時確認／薪資／毛利／戰情室。可獨立開帳，不必先走仲介 |
| **P3** | **系統分析輔助** | P2 之後 | 概念 → 需求文件 → 規格 → 可追蹤 Issue；工程師在控制台收得到指派 |
| **P4** | **仲介平台** | **門檻後** | 非軟體業發案、媒合、合同、拆帳。僅當 P3 驗證「能把需求變成可指派 Issue」之後才開 |

工程師仍用控制台畫執行狀態並上傳；第三方只要符合 [公開回報契約](../product/reporting.md) 也可送。自架工作區改後期。

細節：[產品規格](../product/README.md) · [路線圖](../product/roadmap.md) · [PRD](../product/prd.md)。簡報不要把這段講成安裝包已有。

## 不是什麼

不取代 Jira 或 Cursor。不做汎用 ERP、報稅、勞健保申報。任務面以 GitHub 為準。**不是**產業 OS／模組上架平台（見模啟）。**不是**把仲介當今天就能買的下一刀。

## 下一步

指定一位 Tech Lead、一位 PM。下載 [Releases](https://github.com/sjvann/AI_Project_Console/releases) 安裝包。走完導入後再談授權與規劃中的**公司工作區**時程；系統分析與仲介依路線圖門檻再談。若你們評估產業底座，請以模啟為另一條產品簡報，勿與本線四套混成同一故事。不要把規格書講成安裝包已有。
