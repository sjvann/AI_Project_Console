# 講者重點

對照 [經營層投影片](executive-pitch.html)。每頁先講標題句，再補一個對方公司的例子。數字圖都是**示意**，不要說成客戶實測。現況與規劃分開講；第 12 頁以前只講已出貨的控制台。

## 1. 開場

**要說：** 任務在系統裡，交付在本機。你們已經有 Git、工作單、Cursor 或 Copilot。缺的是把它們編成一套可治理的日常，讓 Agent 接到現場真相。

**不要說：** 我們要取代 Jira、取代 Cursor；或保證產能翻倍。

**若被問「這是給誰用的」：** 經營層看 AI 授權有沒有換成可驗收的交付；PM 管進件到驗收，任務可請 Agent 協助；Tech Lead 讓 Agent 用 MCP 查堆疊；工程師求救帶上下文。同一套 Git 帳號，不必再登一次。

## 2. 痛點

把對方現況講成三個斷層：任務只寫在系統裡、人在表上、AI 與現場脫節。停兩秒，讓他們自己對號。第三張卡要講：Agent 會改碼，但看不到需重編與就緒。

## 3. 不接起來的代價

帶圖表時先聲明「示意」。然後對到他們的損益：工時對不上 Issue，專案毛利是猜的；沒有驗收軌跡，客訴時講不清誰在何時放了什麼。

## 4. 角色定位

重複這句：**本機交付作業系統，接上你們的 Agent。** 明講不取代 Cursor／Copilot，也不把程式碼送到我們的雲。控制台是指揮層與真相來源；Agent 是操作者。

四個角色都要點到 AI：經營層要審計與可驗收交付；PM 可請 Agent 協助但關卡在人；Tech Lead 用 MCP 擋猜與危險操作；工程師求救帶上下文。

## 5. 四層能力

用手比四層：交付作業 → 專案治理 → 人員課責 → Agentic 閉環。強調「同一視窗、同一 Git 帳號」，不是再買三套系統再外掛一個 AI。課責這一層今天是 GitHub 帳號＋工時；外包主檔與費率是第 12 頁的規劃。

## 6. 專案管理

走一遍生命週期：標題與說明就能發 Issue，指派可選。已發出後可暫停、收回或驗收關 Issue。審查與合併仍走 GitHub 與開發台。

已發出的進件不能直接刪；暫停與收回會留言、留紀錄。這句對高層很有用。

## 7. 人員管理

人的主鍵是 GitHub 帳號，不是另一張員工卡。工時從開啟專案起算；滿 8 小時變黃、滿 10 小時變紅。匯出 CSV 對帳走開發台與檔案，不在需求台重做一套。

需求看板看**全部**未關閉與指派（含他人）；開發台任務列預設是「我的＋未指派」。

若有人問外包與月薪：承認現況沒有員工檔，請他們等第 12 頁，不要現場發明功能。

## 8. AI 與 Agentic

先講分工：Agent 改碼，控制台管真相。後端可換（Cursor 預設）。求救帶畫面／Log／編譯／任務。MCP 讓 Agent 回查編譯與堆疊；右側審計看得到成功與被拒。專案問答只讀、不鎖編譯。

**不要說：** 我們自己做了一個更強的模型；或保證 Agent 一次改對。

## 9. 差異

對表，不要攻擊競品品牌。結論：雲端 PM 不管本機堆疊；只用 AI IDE 會改碼但沒閉環、沒審計；自製腳本沒有關卡與對帳。本產品補的是**執行層 + Agentic 閉環**。更細的表見 [競品對照](competitive.md)。

## 10. 為什麼現在買

四個採購理由就夠：90 分鐘導入、工時＋Issue＋PR 一張表、驗收與報帳有關卡、已有的 Agent 接到堆疊真相且動作可審計。企業可改認證主機（GitHub Enterprise）。

## 12. 公司營運層路線圖

**要說：** 規劃中的北極星是軟體工程仲介（尚未出貨）：有軟體需求的公司與工程師成交，抽仲介費；成交後用工作區管人、專案、工時與毛利。工程師仍用控制台上傳。技術是我們營運的 SaaS，不是今天安裝包裡的畫面。

**不要說：** 這些已經在產品裡；或保證下個季度某日交貨；或說我們是派遣公司。

**要指：** [產品規格](../product/README.md) 與 [PRD](../product/prd.md)。這一頁的存在是為了誠實，不是為了把路線圖賣成現貨。

## 13. 收尾

只留兩個下一步：指定 Tech Lead 加 PM，用**他們自己的倉**跑 [90 分鐘導入](../team/trial-90min.md)；若經營層要營運層，會後發規格書，不要在投影上談折扣。可以談規格書，**不可以**把規劃講成已出貨。
