# 需求工作台

標題列「開發／需求」切換工作台。**需求**用來開 GitHub Issue 並追蹤；**開發**走編譯、啟動、承接任務。同一個 Git 帳號，不必再登一次。UAT 畫面問題若自己改得動，仍用開發台「UAT 求救」開 Agent；改不了再來這裡開 Issue。

需求工作台**不**顯示啟動、停止、建置。進件寫在目前工作區的 `docs/product/intake.json`。截圖在 `docs/product/intake-assets/{進件編號}/`。發出 Issue 時會把這些檔提交並推到遠端，Issue 本文附上連結。

左側清單與右側表單中間可拖拉調整寬度；連點分隔線還原。

## 開一張 Issue

左側按「開 Issue」。一筆進件對應一張 GitHub Issue。舊的 `REQ-`／`ECR-` 紀錄仍可開啟，當同一種 Issue 看。

必填：

- 標題
- 說明

可選：

- **指派**：協作者的 GitHub 帳號（發出時寫入 assignee）
- **截圖／附件**：加入檔案或貼上剪貼簿

目標倉由目前專案自動帶入；帶不到時才需填 `owner/repo`。發出前會預覽本文（含進件編號）。

發出時只提交進件相關路徑，不會把工作區裡其他未提交變更一併帶上去。推送失敗仍可選擇只開 Issue，但其他人暫時可能打不開附件連結。

## 生命週期

草稿 → 已發出 → 實作中 → 已驗收

- 尚未建 Issue → 草稿（缺標題／說明時不能發出）
- 已建、尚未指派 → 已發出
- 已指派或已有 PR → 實作中
- 驗收結案或遠端已關 → 已驗收

暫停／收回會蓋在階段上。審查、合併、發行、部署仍走開發台與 GitHub，不在需求台操作。

需求看板會列出此倉**全部未關閉任務與指派**（含他人），不套用開發台「我的＋未指派」過濾。階段由 Issue 狀態推導；阻擋原因會寫在軌道上。

## 刪除、暫停、收回

已發出的進件**不能直接刪**，否則本機表與遠端 Issue 會失聯。

| 動作 | 何時用 | 做什麼 | 不做什麼 |
|---|---|---|---|
| **刪除** | 尚未發出 Issue（草稿） | 從清單拿掉，並刪本機附件 | 不碰 GitHub |
| **暫停執行** | 已發出、尚未驗收 | 在 Issue 與未合併 PR `@` 承辦人留言，進件標成已暫停；前進動作全部擋下 | 不關 Issue、不還原程式 |
| **恢復執行** | 已暫停 | 再留言通知繼續，清掉暫停 | — |
| **通知收回** | 已發出、尚未驗收 | 留言後把 Issue 關成「不計畫進行」，進件留在清單標成已收回 | **不刪紀錄、不還原已入主線的程式** |
| **驗收結案** | 已發出、未被暫停／收回 | 關閉 GitHub Issue | 不合併 PR、不部署 |

暫停與收回可填可選說明。若已有 PR 入主線，收回對話會警告：只通知與關 Issue，程式要另開 Issue 還原。

已驗收不再暫停／收回。要改行為請開新的 Issue。

## 認證對象

大型公司可自建 Git。設定 → 一般，或登入對話框，可改**認證主機**（預設 `github.com`）與種類（GitHub / GitHub Enterprise 可開任務；GitLab 等先可設、任務功能尚未接時會停用）。

`ai-project.json` 的 `github.host` 也可寫此倉的主機。沒填時從 `git remote` 推斷。
