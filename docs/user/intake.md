# 需求工作台

標題列「開發／需求」切換工作台。**需求**走治理與生命週期；**開發**走編譯、啟動、承接任務。同一個 Git 帳號，不必再登一次。

需求工作台**不**顯示啟動、停止、建置。進件寫在目前工作區的 `docs/product/intake.json`，圖片附件在 `docs/product/intake-assets/{進件編號}/`，請跟倉提交。

左側進件列與右側表單中間可拖拉調整寬度；連點分隔線還原。

## 需求與設計變更差在哪

| | **新需求（REQ）** | **設計變更（ECR）** |
|---|---|---|
| 本質 | 從無到有 | 改已經存在的行為或畫面 |
| 必填 | 標題、說明、目標倉 | 再加上現況、期望、影響，並掛設計／架構頁 |
| UI | 勾「這是介面」後附**草圖**（手繪、線框、示意） | 勾「這是介面」後附**現況剪圖**，每張寫要改什麼 |
| 為什麼圖不一樣 | 新畫面還沒得剪，草圖表達意圖就夠 | 改的是現有像素，剪圖才能對到修改處 |

非 UI（API、流程、後端）不必附圖。種類可在表單切換；已發出後請不要為了省事改種類，應另開進件。

## 生命週期

一筆進件（需求或設計變更）依序：

草稿 → 設計就緒 → 已拆解 → 已發出 → 實作中 → 驗證中 → 可審查 → 已入主線 → 已發行 → 已部署 → 已驗收 → 已報帳

關卡：

- 沒有驗收條件不能發出 Issue。發出前會預覽本文（含進件編號與驗收條件）。
- 設計變更要填現況、期望、影響，並掛上 `docs/product` 或 `docs/engineering` 頁。
- 介面新需求缺草圖、介面設計變更缺剪圖或修改說明，不能離開草稿。
- CI 未綠不能合併。
- 驗收要勾完條件，相關 PR 已入主線，且已部署或明示「本進件不部署」，才關 Issue。

遠端建置與部署仍由該 Git 主機的 workflow 跑；控制台負責發出、監看、擋關與觸發。

需求看板會列出此倉**全部未關閉任務與指派**（含他人），不套用開發台「我的＋未指派」過濾。階段由 Issue／PR／CI 推導；阻擋原因會寫在軌道上。

開發工作台的任務列會顯示同一套 PR／CI 燈號，清單過濾規則不變。

## 刪除、暫停、收回

已發出的進件**不能直接刪**，否則本機表與遠端 Issue 會失聯。

| 動作 | 何時用 | 做什麼 | 不做什麼 |
|---|---|---|---|
| **刪除** | 尚未發出 Issue（草稿／設計就緒／已拆解） | 從清單拿掉，並刪本機附件 | 不碰 GitHub |
| **暫停執行** | 已發出、尚未驗收 | 在 Issue 與未合併 PR `@` 承辦人留言，進件標成已暫停；前進動作全部擋下 | 不關 Issue、不還原程式 |
| **恢復執行** | 已暫停 | 再留言通知繼續，清掉暫停 | — |
| **通知收回** | 已發出、尚未驗收 | 留言後把 Issue 關成「不計畫進行」，進件留在清單標成已收回 | **不刪紀錄、不還原已入主線的程式** |

暫停與收回可填可選說明。若已有 PR 入主線，收回對話會警告：只通知與關 Issue，程式要另開設計變更還原。

已驗收或已報帳不再暫停／收回。要改行為請開新的設計變更。

## 認證對象

大型公司可自建 Git。設定 → 一般，或登入對話框，可改**認證主機**（預設 `github.com`）與種類（GitHub / GitHub Enterprise 可開任務；GitLab 等先可設、任務功能尚未接時會停用）。

`ai-project.json` 的 `github.host` 也可寫此倉的主機。沒填時從 `git remote` 推斷。

## 工時對帳

工程師在開發工作台匯出 CSV 後，需求台「匯入工時 CSV」可對上已發出的 Issue 編號。對上的進件會標成已報帳。
