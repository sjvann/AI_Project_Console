# 畫面導覽

控制台是桌面視窗，可同時開多份、各自管不同專案。單一視窗由上到下：標題列 → 專案列（內含 **GitHub Pulse**）→ 工具列 → 摘要列 → **工作區頁籤**（服務／專案／文件，左右成對）→ 狀態列。需求工作台沒有開發工具列，但仍看得到 Pulse 與 GitHub 操作台。

可同時開多個視窗。後開的視窗標題會帶專案名，且不會改掉先開那個視窗正在管的目錄。第二個視窗啟動時不會自動還原上次專案，請從歷史或「選擇專案目錄」載入。

## 標題列

| 項目 | 作用 |
|------|------|
| 名稱與版本 | 目前安裝的控制台版號；開啟專案後會在前面加上專案名，方便多視窗辨識 |
| **開發／需求** | 切換工作台。開發＝編譯與承接任務；需求＝開 GitHub Issue、指派、驗收。需求台左右兩欄中間可拖拉。見 [需求工作台](intake.md) |
| **本次／今日工時** | 從開啟目前專案到現在、以及今天各專案合計的工作時數。滿 8 小時會變黃、滿 10 小時變紅。點擊打開週／月／季／年儀表板與報帳單 |
| **設定** | 外觀、Agent、MCP、工具權限、專案問答，以及檢查控制台更新。見 [設定](settings.md) |
| **GitHub 操作台** | 綠框，在帳號旁邊。開發與需求台都看得到。點了展開四欄 Hub。有未提交時顯示數量。快捷鍵 Ctrl+G |
| GitHub 帳號燈 | 綠＝已登入且無待處理；紅＝尚未登入；黃＝有未提交、未發布或需同步。點一下同樣開啟操作台。未登入顯示「未登入」 |
| **離開** | 關閉控制台視窗。工作區不乾淨或還有未發布提交時會警示；可先提交／發布，或按「強行關閉」。本機 Agent 會再問是否關閉這個專案的 IDE 視窗（不會關掉其他專案） |

## 專案列

| 項目 | 作用 |
|------|------|
| 專案名稱／路徑 | 尚未選擇時會提示你選目錄 |
| **分支** | 目前 git 分支。點一下可切換或建立新分支 |
| **歷史專案** | 最近開過的目錄（最多 12 個仍存在的路徑） |
| **選擇專案目錄…** | 本機資料夾選擇 |

| **關閉專案** | 卸下目前工作區。工作區不乾淨或尚未發布時會警示；可先提交／發布，或按「強行關閉」。本機 Agent 會再問是否關閉這個專案的 IDE 視窗 |
| **啟動時還原上次專案** | 下次啟動自動載入。同時開第二個視窗時只有第一個會還原 |

## GitHub Pulse

開啟專案後出現在專案列下方，開發與需求台都有。一眼看分支、未提交／領先／落後，以及**現在該做的那一步**。標題列右側的 **GitHub 操作台** 是綠框按鈕，點了會開四欄 Hub。

| 項目 | 作用 |
|------|------|
| **分支** | 與專案列相同，點一下切換或建立分支 |
| 工作區摘要 | 未提交、↑ahead、↓behind、或「乾淨」 |
| **主按鈕** | 只顯示一個：提交、同步、發布、建立 PR、Actions，或預設分支已同步時的「發行 Release…」。功能分支已就緒時改為開操作台 |
| **CI／PR** | 登入且專案由 GitHub 管理後出現。綠＝通過、主色＝進行中。剛推送後失敗才黃；歷史失敗不亮警報。點一下看摘要。控制台不能修 CI |

操作台是畫面中間展開的四欄：**日常節奏**、**遠端協作**、**發行與 CI**、**接入**，下方是 Issue 任務清單。見 [GitHub](github.md)。

## 工具列

| 按鈕 | 作用 |
|------|------|
| **啟動** | 依啟動順序啟動尚未在線的服務。有 `preStart` 的會先跑腳本；有 `dependsOn` 的會先起相依並等到就緒 |
| **停止全部** | 停止此工作區控制台管到的服務 |
| **開啟前端** | 先確保前端（與 `dependsOn`）就緒，再開預設前端網址；或「開啟全部 URL」同樣先起再開 |
| **UAT 求救** | 填說明／貼截圖，交給 Agent。見 [卡住時怎麼辦](help.md) |
| **執行求救** | 把目前選取服務的 Log／啟動失敗交給 Agent。沒有錯誤時按鈕停用 |
| **編譯求救** | 把最近一次編譯或測試失敗交給 Agent。沒有失敗時按鈕停用 |
| **建置** | 編譯過期項目／全部服務／全部專案（含測試）／跑測試 |
| **部署** | 發佈目標設定與狀態。見 [部署](deploy.md) |
| **文件** | 建立體系、AI 補齊、本機 DocFX 預覽、GitHub Pages。見 [專案文件](docs.md) |
| **專案問答** | 跳出視窗，用本機堆疊事實回答。見 [卡住時怎麼辦](help.md) |
| **環境體檢** | 跳出視窗：git／gh／Agent／**工作區語言環境**／文件狀態／目前專案服務清單。缺少 Python、Node 等時可一鍵安裝 |

建置「全部專案」會編譯目錄內偵測到的全部專案（含測試），可能要數分鐘，執行前會確認。「跑測試」依技術棧執行（.NET 為 `dotnet test`，有方案就跑方案），不是 IDE 裡的測試總管。

## 工作區：服務／專案／文件

頁籤在左右欄**上面一層**。切一頁，左右一起換。連點「服務」「專案」可全部展開或收合群組。中間分隔線可拖拉；連點還原各半。

| 頁籤 | 左 | 右 |
|------|----|----|
| **服務** | 服務清單 | 服務 Log |
| **專案** | 編譯專案清單 | 建置／測試輸出 |
| **文件** | `docs/` 目錄 | 編輯／預覽 |

任務在 [GitHub 操作台](github.md)，不佔頁籤。專案問答與 MCP 審計改為視窗，不佔右側頁籤。

### 服務

每一列：線上／離線、名稱、一句用途、連接埠、操作。離線顯示「啟動」；有 `openUrl` 時也顯示「開啟」（離線會先起自己與相依再開瀏覽器）。線上另有「重啟／停止」。用途優先用 `ai-project.json` 該服務的 `description`，沒寫則用掃描到的專案用途；沒有就不顯示。

- **開啟** — 有 `openUrl` 時顯示（隨宿主須宿主在線）。會先起自己與 `dependsOn` 並等到就緒，再開瀏覽器；已在線則直接開。Alt 略過可選相依。硬相依失敗則不開 URL。進行中該列顯示「開啟中…」，開啟／啟動／重啟／停止會停用，避免連點
- **啟動** — 離線且可單獨啟動時顯示。有 `dependsOn` 時會先起相依；Alt 略過可選相依，Shift 只起自己。進行中顯示「啟動中…」，該列按鈕同樣停用直到健康檢查對上或失敗
- **重啟／停止** — 線上且可單獨啟動時顯示。進行中顯示「重啟中…」／「停止中…」
- **群組列** — 頂層群組名稱旁可顯示 `groups[].description` 短說明；操作作用於該群組（含次群組）。開啟／啟動都會補齊各項 `dependsOn`
- **依 xxx** — 這個項目啟動或開啟時會先起列出的服務（`optional` 可略過）
- **隨 xxx** — 這個項目掛在另一個行程上（例如 Web 跟 API 同一 process），不要單獨啟動
- **失敗** — 滑鼠停上看啟動錯誤；右側 Log 有完整輸出

`ai-project.json` 的 `group` 可用 `Lab/HL7` 表示次群組；同一群組若名稱開頭自然分成兩組以上（例如 HL7…／SFTP…），也會自動出現次群組。沒有服務時：放清單，或確認 `launchSettings.json` 有 `applicationUrl`。

選一個服務後，右側顯示它的輸出。可搜尋、跟隨最新、清空顯示（不清實體檔）、開啟 `.ai_project/logs` 資料夾。線上服務異常時，工具列、服務列與右側 Log 都有 **執行求救**。

### 專案

每一列：專案名、一句用途、類型／語言／上次編譯、狀態徽章、**編譯**。編譯失敗那一列會多 **編譯求救**。右側是建置／測試輸出，顯示 `{已完成}/{預計}`。工具列也有同一顆 **編譯求救**（沒有失敗時停用）。報告也寫在 `.ai_project/build-reports/`。

用途對**每一個**掃描到的專案都要有，不限可啟動服務。來源順序：`ai-project.json` 的 `projects` → 專案檔 `Description`／`PackageDescription` → `package.json`／`pyproject.toml`／`Cargo.toml`／`pom.xml` 的 description。沒有這些欄就留空，不讀 README。開啟或按「重新掃描」時，控制台會寫一份清單到 `.ai_project/product-purposes.md`（執行期檔，不進 git）。缺用途的專案會列在該檔「尚未提供」。

| 徽章 | 意思 |
|------|------|
| 需重編 | 原始碼比輸出新。滑鼠停在列上看是哪個檔觸發 |
| 未建置 | 還沒編譯過 |
| 最新 | 控制台自己編譯成功且來源沒再改 |
| 編譯中 | 進行中（列會用主色標示） |
| 失敗 | 看右側建置輸出，可用編譯求救 |

勾選「只看需重編」可過濾。狀態不對、或目錄裡剛多了專案時按「刷新」（與專案列「重新掃描」相同，會重掃目錄並更新編譯徽章）。`appsettings`、`data/*.json` 通常**不**應觸發需重編。

### 文件

列出目前專案 `docs/` 的目錄樹。先選資料夾裡的檔，再在右側編輯。沒有骨架時按「建立體系」；也可「新增文件」。多餘的頁用工具列、檔案列或右側的「刪除」，會先確認再移除本機檔。見 [專案文件](docs.md)。

勾選「本頁預覽」只看目前這頁；「網站預覽本頁」才開 DocFX 網站的目前這頁（設定檔則開首頁）。可儲存、AI 補齊本頁。

### 任務（在 GitHub 操作台）

登入 GitHub 後，操作台下方列出目前倉庫的開放 Issue。摘要列「我的任務」也會打開操作台。

- **我的任務** — 指派給你的項目。點標題先看內文（含圖），再討論。不是問題就**結案**；自己做得到就開分支、建 PR。處理不了才 **請 Agent 協助**。PR 合併或結案才關閉任務。完整討論也可按「在 GitHub 開啟」。
- **未指派** — 沒有負責人的項目，預設可開合。點標題開瀏覽器；按 **接受** 指派給自己，就會出現在上方

沒有 GitHub 遠端的本機目錄不會要求登入。

### MCP 審計

摘要列「MCP 拒絕」打開對帳單視窗。Agent 透過 MCP 呼叫控制台（成功或被拒）都會寫進來。尚無紀錄通常表示還沒接 MCP，不是故障。見 [MCP](../agent/mcp.md)。

### 專案問答

工具列按鈕，與環境體檢同一排（開發台）。點了跳出視窗，用本機堆疊事實回答（預設接 Ollama）。**不會**外開 Cursor，也不會鎖住啟動／編譯。設定裡可點來源範本、測連線並記住多組端點。見 [卡住時怎麼辦](help.md)。

## 工時儀表板

標題列的工時徽章打開這個視窗。工時從**開啟專案**起算，切換或關閉專案會切開時段，寫入本機 `%LOCALAPPDATA%\AI_Project_Console\work-hours.json`。尚未選擇專案時不計時。同一人用 GitHub 帳號歸檔（`personKey` = `github:帳號`）；還沒登入時先記在本機 Windows 使用者下，登入後會把尚未歸戶的時段併到這個帳號。另一個 GitHub 帳號的時段不會混進來。舊版沒有專案欄位的時段會標成「未掛專案」，儀表板看得到，但不列入報帳單。

| 項目 | 作用 |
|------|------|
| **週／月／季／年** | 切換視圖。週、月列出每一天；季、年只列出有上班的日子，圖表改成各月合計 |
| **儀表板／報帳單／狀態圖／公司** | 儀表板看圖表與作息；報帳單看各專案可報帳時數、已關閉 Issue、開啟或合併的 PR；狀態圖塗本機投入；公司分頁只讀顯示選定工作區給你的身分、派工、最近一次上傳結果與薪資條（不是戰情室） |
| **各專案時數** | 期間內每個專案的合計。點一列只看該專案的圖表；同一 GitHub 倉（`owner/repo`）會併在一起 |
| **上一週／下一週…** | 前後期間。不能翻到未來。這只篩本機工時，不篩公司派工 |
| **圖表** | 每天（或每月）時數。週／月圖上的虛線是 8 小時。季／年點某月會鑽到該月 |
| **每日時段** | 當天每一段開啟～離開，例如 `09:12–12:40`。跨午夜會拆成兩天 |
| **匯出工時單** | 選一個資料夾，寫入 Markdown 報告與兩份 CSV（時數、Issue／PR）。欄位固定，方便把多人檔案接到同一張表 |
| **送到〔這家公司〕** | 把目前期間的本機時段送到已啟用的申報目的地。成功後時段在公司工作區「公開回報 → 待確認」。本機檔仍在 |

關掉視窗、按「離開」，或程式被關掉時，會把目前這段工時結束。若當機，下次開啟會用最後一次心跳（約 30 秒）當作離開時間。尚未用 GitHub 歸戶就匯出時，會提醒 `person_key` 還是本機使用者，PM 較難對人。設定「申報公司」還沒加入並啟用時，這個按鈕會停用，工時仍可匯出。

## 狀態列

「關閉控制台不會停止服務」。行程與 Log 寫在選定專案的 `.ai_project/`。要停服務請按「停止全部」或各列的停止。
