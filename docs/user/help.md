# 卡住時怎麼辦

控制台把「何時求救、帶什麼上下文」準備好；真正改碼的是你選的 **Agent 後端**（預設 Cursor）。後端只負責開啟工作區／Agent，不經控制台的雲端 API Key。

還沒選後端？見 [Agent 後端](../agent/backends.md) 與 [設定](settings.md)。

## 三種求救

| 時機 | 你怎麼按 | 帶給 Agent 的內容 |
|------|----------|-------------------|
| 畫面不對、操作卡關 | 工具列 **UAT 求救** | 你填的標題／說明，可加檔案或貼上截圖 |
| 服務起得來但行為錯、Log 有例外 | 工具列 **執行求救**（或服務列／右側 Log 同一顆） | 該服務近期 Log |
| 編譯或本機測試失敗 | 工具列 **編譯求救**（或專案列／右側建置輸出同一顆） | 建置或測試錯誤（不另寫求助檔）。遠端 CI 失敗：點摘要列 CI →「開啟最新」到 GitHub 看 log |
| 要做指派給你的 Issue | GitHub 操作台 → 點標題先看內容 → **請 Agent 協助**；做完後再留言或開 PR | Issue 標題、內文與網址 |

送出前會預覽提示。確認後：

- **Cursor**：開啟專案並用 deeplink 開 New Agent
- **Claude Code／Aider／Codex**：用 CLI 或新終端機帶入提示
- **VS Code／Windsurf**：開資料夾並複製提示，請你在對談裡貼上
- **自訂命令**：依設定的 `{root}`、`{promptFile}`、`{prompt}` 執行

提示會寫入專案 `.ai_project/agent-prompts/`。若已接 MCP，提示會要求 Agent 用 `build`／`stack_status` 驗證，而不是只改檔。見 [MCP](../agent/mcp.md)。

## UAT 求救步驟

1. 按「UAT 求救」。
2. 填標題與說明（說明會直接進提示，請寫重現步驟）。
3. 「加入檔案」或「貼上截圖」。截圖會存到 `.ai_project/uat-reports/`。
4. 確認送出。依後端開啟 Agent 或複製提示。

## 專案問答（不外開 IDE）

工具列「專案問答」跳出視窗。用設定裡的 **OpenAI 相容**端點在控制台內回答，並本機呼叫唯讀堆疊工具（值班摘要、狀態、Log、體檢、git、審計）。

- **不會**外開 Cursor，也**不會**佔用啟動／編譯的忙碌鎖。等回覆時仍可切頁、看 Log、按啟動。
- 只談**目前開啟的專案**。要改碼、編譯、啟停：用按鈕或既有求救。

**怎麼開**

1. 設定 → 專案問答：填 Base URL 與模型。本機 [Ollama](https://ollama.com/) 預設 `http://127.0.0.1:11434/v1`、模型如 `llama3.2`，API key 可空白。OpenAI／Groq 則改 URL 並填 key。
2. 點工具列「專案問答」。可點建議題（離線／需重編／MCP 真的失敗時會置頂並標「建議」），或自己打字。
3. 要中斷按「取消」。

尚未設定模型時，分頁會引導你去設定。

## 還是不行

1. 按「環境體檢」，看缺哪個工具。
2. 對照 [常見問題](troubleshooting.md)。
3. 服務 Log 與建置輸出仍是真相來源；先讀完再求救，Agent 才有材料。
