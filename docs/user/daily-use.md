# 日常操作

假設你已經[安裝並選好專案](getting-started.md)。這頁是每天重複的路徑。標題列可切換**開發**（編譯、啟動、承接任務）與**需求**（進件、發出、審查到驗收），見 [需求工作台](intake.md)。

## 建議流程

```
打開控制台（可自動還原上次專案）
    → 已接遠端時先自動同步目前分支
    → 看專案列「分支」與 Pulse：離線？需重編？未提交？文件缺骨架？
    → 有需重編：建置 → 編譯過期項目
    → 按「啟動」
    → 就緒後「開啟前端」
    → 出事：工具列「執行求救」或「編譯求救」
    → 改完碼要留下紀錄：Pulse 主按鈕「提交…」（或 Ctrl+G 開操作台）
    → 下班：停止全部（可選）。關視窗不會停服務
```

## 啟動服務

1. 確認摘要列沒有大片「需重編」（過期二進位常會讓服務起了卻行為舊）。
2. 按工具列 **啟動**。控制台依 `startOrder`（有清單時）或掃描順序啟動離線服務；若服務宣告了 `dependsOn`，會先起相依並等到就緒。
3. 某個服務有前置腳本（`preStart`／`ensure`）時，**先跑該服務自己的腳本**，成功才啟動行程。失敗訊息在該服務 Log。各服務前置彼此獨立，不會用這一欄去起另一條產品線。
4. 列變成「線上」、摘要「就緒」增加即成功。

只起一個：在離線服務列按「啟動」。有 `dependsOn` 時會先起相依（列上「依 xxx」）。**Alt＋啟動**略過可選相依；**Shift＋啟動**只起自己（硬相依會再確認）。掛在別的服務上的項目（「隨 xxx」）會跟著宿主走。一整組：按群組名稱旁的「啟動」（該組離線項會各自補齊 `dependsOn`，必要時會先起組外相依）。

各應用仍可單獨開；連不到相依時應由該應用自己說清楚。跨線先起是控制台的事，不要在應用程式裡啟動別的服務。

## 停止與重啟

| 動作 | 位置 |
|------|------|
| 停一個 | 線上服務列「停止」 |
| 重啟一個 | 線上服務列「重啟」 |
| 停／啟／重啟一整組 | 群組名稱旁的對應按鈕（含次群組） |
| 全停 | 工具列「停止全部」 |

關閉控制台、關閉專案、離開程式，都**不會**自動停服務。忘記停時，下次打開同一目錄仍看得到線上狀態（健康檢查仍打得到）。

## 編譯

| 選單 | 何時用 |
|------|--------|
| **編譯過期項目** | 日常預設。只編「需重編」的 |
| **全部服務** | 服務對應的專案都重編一次 |
| **全部專案** | 含測試專案，只編譯、不跑測試，時間較長，會先確認 |
| **跑測試** | 一次完整 `dotnet test`。有方案就跑方案。不是 IDE 測試總管 |
| 列上的 **編譯** | 只編那一個 `.csproj` |

進行中請看右側「建置輸出」的 `3/12` 這類進度。結束後：

- 成功且沒再改檔 → 徽章應變「最新」
- 失敗 → 建置輸出看錯誤；按「編譯求救」把錯誤交給 Agent（不另寫求助檔）

控制台**自己編譯成功**且來源沒再改，應顯示「最新」，即使磁碟上 DLL 時間戳看起來較舊。若編譯成功仍顯示需重編：把滑鼠停在該列看原因檔，再按「刷新」。工作區開著時若又新增了專案，按專案列 **重新掃描**（或專案頁「刷新」）才會列入。

## 看 Log 與開網頁

1. 點左側服務列（反白＝已選）。
2. 右側維持服務 Log（已在「服務」頁籤）。可搜尋、勾選「跟隨最新」。
3. 「開啟資料夾」會開 `.ai_project/logs`。
4. 有「開啟」連結或工具列「開啟前端」可開瀏覽器。

Log 顯示被你「清空」只影響畫面，檔案還在。

## 專案文件

摘要列「文件」不是就緒時：工具列 **文件 → 建立／補齊體系…**，在右側改 Markdown，再提交。要給別人看線上版：啟用 GitHub Pages 後發布。見 [專案文件](docs.md)。

## 完成指派的 Issue

GitHub 操作台 → 點「我的任務」標題，**先看內容**：

1. **看內文**，確認要做什麼。
2. **請 Agent 協助**：把這則 Issue 交給後端 Agent 在工作區實作。
3. Pulse **提交…**，再 **發布（push）**。若還在 `main`，完成後可「為此任務建立分支」。
4. **送出回應**（可選）或 **建立 PR**。留言不會關閉任務；PR 合併後才會。說明會寫入 `Closes #編號`。

還沒切到功能分支就按「建立 PR」，控制台會說明原因，而不是丟出難懂的 `gh` 錯誤。

## 一天結束

1. 有未提交變更：Pulse 主按鈕「提交…」，或 Ctrl+G 開操作台。見 [GitHub](github.md)。
2. 有尚未發布的提交：Pulse 會改成 **發布（push）**。新分支也要先發布。若設定了「發布前先跑本機測試」，測試沒過就不會推。推送後 Pulse 會監看遠端 CI；有 PR 時也看檢查能不能請人審。沒有 CI workflow 可在操作台「發行與 CI」按 **補齊 CI workflow…**。
3. 不需要服務繼續跑：按「停止全部」。
4. 工作區乾淨、與遠端一致後再開「關閉專案」或「離開」。若仍有未提交／未發布，警示可「留下」去處理，或「強行關閉」。本機 Agent（IDE／終端機）會再問是否一併關閉該應用程式；雲端後端不會問。設定存在本機 `%LOCALAPPDATA%\AI_Project_Console\settings.json`，專案執行期檔在該倉的 `.ai_project/`。
5. 標題列「本次／今日」是目前專案這段、以及今天各專案合計的工時。滿 8 小時請考慮收工；點進去可看週／月／季／年、各專案時數，並匯出報帳單給負責人。見 [畫面導覽](interface.md#工時儀表板)。
