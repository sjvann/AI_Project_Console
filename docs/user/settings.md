# 設定

標題列「設定」打開偏好設定。分六個分頁。多數項目按「儲存」才寫入；「啟動時還原上次專案」「同時開啟 Agent」在主畫面勾選也會立刻記住。

設定檔位置（Windows）：`%LOCALAPPDATA%\AI_Project_Console\settings.json`。工時紀錄在同一資料夾的 `work-hours.json`（依專案切開時段；匯出的工時單是另外選資料夾寫入的 Markdown／CSV）。

## 一般

| 項目 | 作用 |
|------|------|
| 外觀 | 淺色／深色 |
| 啟動時還原上次專案 | 下次自動載入最後一個目錄。同時開第二個控制台時，只有第一個視窗會還原，避免兩個視窗搶同一個專案 |
| 載入專案時開啟 Agent | 選好目錄後一併打開目前後端的工作區 |
| 發布前先跑本機測試 | 發布（push）或提交後再推之前，先跑一次完整測試。沒過就不推。詳細案例請在 IDE 跑 |
| 預設認證主機／種類 | 登入打哪一台 Git（`github.com` 或企業主機）。GitHub 相容才能開 Issue；其他種類可先設定 |
| **檢查更新** | 查 GitHub Releases 是否有新版。會先問要不要包含 RC／預發行。已安裝版會下載 setup 並啟動安裝程式；若最新 Release 沒有安裝包則改開 GitHub 頁 |
| **從檔案更新…** | 選本機 `*-setup.exe` 或 zip，略過下載直接安裝。從原始碼執行時不能覆蓋開發目錄 |

## 申報公司

把工時送到哪一家公司工作區。這一頁上半是**已加入的公司**，下半虛線框是**空白表單**（還沒加入）。不要把下面三個空欄當成第二家公司。

| 項目 | 作用 |
|------|------|
| **已加入** | 每一張卡片是一家已存的公司：顯示名、工作區網址、回報金鑰。先「測試連線」通過再「啟用這家公司」 |
| **新增一家公司** | 空白表單。填完按「加入這家公司」才會出現在上方清單 |
| **加入本機示範** | 把網址填成 `http://localhost:5100`；金鑰仍要從該站「公開回報」複製，再測試、啟用 |
| 工時儀表板 | 「公司」分頁顯示這家給你的身分、派工與薪資條；「送到〔這家公司〕」後，對方在工作區「公開回報」看待 PM 確認。本機 `work-hours.json` 仍保留 |

未加入任何一家時，控制台其餘功能照常。

## Agent

控制台決定**何時**求救、提示裡帶什麼；後端只決定**在哪裡**跑。

1. 選後端（Cursor、Claude Code、Aider、Codex CLI、VS Code、Windsurf、自訂）。
2. 看偵測摘要：可用／找不到。
3. 自動偵測失敗時，填「CLI 路徑覆寫」。
4. 自訂後端再填命令與參數範本。可用變數：`{root}`、`{promptFile}`、`{prompt}`。

各後端差異見 [Agent 後端](../agent/backends.md)。求救用法見 [卡住時怎麼辦](help.md)。

## MCP

把「本控制台」和其他 MCP 寫進**目前專案**的 `.cursor/mcp.json`，讓 Agent 能查堆疊、編譯、啟停。清單只顯示專案檔，不含使用者全域 `~/.cursor/mcp.json`。本控制台那一筆會指向 **AI_Project 控制台產品**（`--mcp`），`--root` 才是目前受管理的專案；不會寫相對路徑 `src/AiProject.Console.Mcp`。

一般使用者最低限度：

1. 已開啟專案。
2. 在「已引用的 MCP」對「本控制台」按「加入」，或用下方下拉加入。
3. 重新載入 Cursor（或你的 IDE）。
4. 點摘要列「MCP 拒絕」打開審計視窗後會出現呼叫紀錄。

也可加入建議範本（GitHub、Context7）或「自訂」填命令／URL。細節與政策見 [MCP](../agent/mcp.md)。

「複製本控制台設定」可貼到使用者全域 mcp.json。「開啟 mcp.json」用系統編輯器開專案檔。

## 工具權限

限制 Agent **透過 MCP** 能做的事（與你在畫面按啟動無關）。

| 模式 | 效果 |
|------|------|
| 全部可用 | 已知工具都可呼叫；`stop_all` 預設仍需確認 |
| 唯讀 | 只能看狀態／Log／審計，不能編譯或啟停 |
| 自訂白名單 | 只暴露你加入的工具 |

單一工具可設允許／需確認／禁止。專案若已有 `.ai_project/mcp-policy.json`，會覆蓋這裡的同名欄位。可按「寫入專案政策範本」讓團隊共用。

## 專案問答

工具列「專案問答」用的端點。點範本帶入網址與模型，再按「測試連線」確認來源有回應。問答會呼叫本機工具，因此清單只列出支援 function calling 的模型；Gemma、嵌入模型等只會聊天的會略過。

| 項目 | 建議 |
|------|------|
| **來源範本** | 一鍵帶入：本機 Ollama、LM Studio、OpenAI、Groq、OpenRouter，或自訂 `/v1` 端點 |
| Base URL | 本機 Ollama：`http://127.0.0.1:11434/v1` |
| API key | 本機可空白；雲端相容 API 必填 |
| 模型 | 例如 `llama3.2`、`qwen2.5`。測連線成功後可從清單點選。本機 Ollama 若還沒有該模型，可按 **pull llama3.2** 下載。不要用 Gemma 3 |
| **測試連線** | 呼叫端點 `/models`（必要時改送極短 chat）。成功會顯示「來源正常」，並只列出可用模型 |
| **pull** | 僅本機 Ollama。把建議模型下載到本機，過程可取消。完成後會再測一次連線 |
| **記住目前** | 把這組網址／金鑰／模型存下來，之後用「已記住」下拉切換 |

按「儲存」才寫入設定檔。可同時記住本機與雲端兩組，不必每次重填。

用法見 [卡住時怎麼辦](help.md)。
