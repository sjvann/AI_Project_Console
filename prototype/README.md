# 規劃雛型（兩套獨立產品）

**這不是出貨產品。** 給產品、設計、工程走讀兩套機制。工程師控制台已出貨，本雛型**不**模擬。

| 產品 | 做什麼 | 不做什麼 |
|------|--------|----------|
| **仲介平台** | 管理兩造、平台／專案公告、撮合、合同、傭金金流 | 派工、甘特、工時、戰情室 |
| **公司工作區** | 需求公司回到自己的專案管理：戰情、客戶、專案、人員、派工、工時確認、毛利 | 媒合、抽成、認證發案 |

兩者只在「傭金入帳後把成交事件交給工作區」交換資料。品牌色對齊控制台（綠 `#0b6e56`）。互動狀態在 `sessionStorage`。

## 啟動

```bash
cd prototype
npm install
npm run dev
```

瀏覽器開 http://127.0.0.1:5173 。建置：`npm run build`。

## 建議走讀

### 1. 仲介平台（兩造 → 公告 → 撮合 → 傭金）

1. 門廳選 **仲介平台**。身分先用 **訪客**，打開任一專案公告，按「應徵」→ 被拒。
2. 切 **工程師·未認證**，再應徵 → 人話請去認證。可在「兩造」勾「GitHub 對不上」。
3. 完成 GitHub 認證（或切 **工程師·已認證**），應徵成功。
4. 切 **需求窗口·已認證**，用「發布」走完精靈並刊登。看「平台公告」。
5. 在公告頁邀請或在「撮合」按「雙方接受」→ 合同。
6. 雙方確認 → **開立仲介費應收** → **模擬付款** → 入帳。仲介主流程結束。
7. 「把成交事件交給工作區」→ 工作區「仲介來件」。

### 2. 公司工作區（成交後自己的專案管理）

1. 門廳或右上角切 **公司工作區**。不必先有仲介成交：已有內部專案「週報自動化」。
2. 經營層看戰情室；PM 看專案／派工（點格子改小時）；人資看人員。
3. 「仲介來件」接手後，名冊出現專案外包、專案從公告投影。
4. 「工時確認」處理控制台送來的時段（雛型標明來源，不重做繪圖）。
5. 可自行立案，不必經仲介。

右上角可切產品。**重設範例** 清掉本次操作。
